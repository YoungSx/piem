# 记录聊天滚动条卡住的现场

[English](scroll-diagnostics.md)

适用情况：聊天滑块拖到中途就不动，松开重抓也一样，但点 **最新** 可以到底。
这与“自动追底停了”是不同故障。原因仍在调查；下面的步骤只收集证据，不安装修复。

## 只需记录一次

1. 保持聊天停在卡住的位置。Windows/Linux 按 **Ctrl+Shift+I**，macOS 按
   **Cmd+Option+I**，打开 Obsidian 开发者工具，选择 **Console**。如果打开后
   故障就消失，请直接说明：窗口布局变化可能影响这个故障。
2. 复制[诊断脚本](../scripts/diagnose-chat-scroll.js)的全部内容，粘贴到控制台并
   运行。保持聊天面板可见。脚本使用当前聚焦的 Obsidian 文档，也支持弹出窗口。
3. 向下拖一次，松手，再拖一次，然后点 **最新**。滚动停止后，控制台会打印
   **Piem 滚动诊断报告**。没有报告时，运行 `piemScrollProbe.stop()`；
   60 秒后也会自动停止。再次运行 `piemScrollProbe.stop()` 会返回同一份报告。
4. 把报告发回来，并说明记录时是否仍卡住。另附命令面板里的 **显示调试信息
   （Show debug info）**，以及是否调过 Obsidian 缩放或系统显示缩放。
   分享前先检查调试信息，它与本脚本严格限定内容的报告是两份数据。
   应用更新后仍可能使用旧安装器和旧 Electron，见
   [Obsidian 的安装器更新说明](https://help.obsidian.md/updates)。

无需安装插件或重新构建。阅读后只粘贴上面链接中的脚本；它不会下载或执行其他代码。
这是桌面开发者工具，尚未在 iOS、Android 中验证。

## 会记录什么

报告包括浏览器／Electron 版本、窗口尺寸和缩放、消息区及最多七层祖先的尺寸和
相关 CSS、滚动位置、滚轮、消息区本身聚焦时的翻页按键、拖动中的鼠标坐标，以及 DOM 变化和尺寸
通知的次数。最多保存 240 条事件及 24 条操作边界。它不读取聊天文字、笔记名、
路径、输入框内容、输入框里敲的键、密钥或任意 DOM 属性，不联网、不写笔记、不写剪贴板。

脚本不主动滚动，也不修改页面。停止时会断开观察器、移除监听器、清除定时器，
释放采样的 DOM 引用。重复粘贴会先停止上一次记录。

## 怎样看证据

- 比较 `beforeLatest[0].scrollTop` 与 `final[0].scrollTop`：末次位置更大，表示
  点击 **最新** 后到达了更远的位置。报告也会列出期间的滚轮和已采样的翻页按键，不能
  自动认定只有点击造成了移动。焦点位于链接或折叠控件时的翻页按键不记录。
- `scrollHeight - clientHeight` 是脚本当前可见的滚动范围。原生拖动提前停止，
  而 **最新** 能继续，应该查拖拽与命中区域，不能直接断言后面的内容不存在。
- 祖先的范围和裁切／隔离样式用于分清内外滚动条。任意主题类名、笔记属性都不记录。
- 没记录到鼠标事件，不代表没抓住滑块：浏览器自己的滑块可能吃掉事件。尺寸通知
  为零也不代表内容没长高；图片、字体加载可能不改变消息区外框，却改变内容高度。
- 开始、点击 **最新** 前、结束时会读取布局，这可能促使浏览器完成未完成的排版。
  鼠标移动采样不读几何信息，但读取滚动位置也可能影响时序。如果记录本身让故障
  消失，请说明。这个工具提供证据，不自动给出诊断。

脚本不打进 Piem 发布包，也不会自行启动。
