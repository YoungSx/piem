# 設定

[← README に戻る](../README.ja.md) · [English](settings.md) · [简体中文](settings.zh-CN.md) · [繁體中文](settings.zh-TW.md)

**設定 → Piem** の下には Models、Chat、Extensions、General の 4 ページがあります。

## Models

一度だけ開けばよいページです。それ以外はすべて実用的な既定値を持っています。

**プロバイダー**はあなた自身のエンドポイントです。Piem は何もホストしません。
プロバイダーはベース URL、API キー、そしてワイヤープロトコルで構成されます。

| プロトコル | 対象 |
| --- | --- |
| `openai-completions` | OpenAI 互換の `/chat/completions` エンドポイント |
| `openai-responses` | OpenAI の Responses API と互換エンドポイント |
| `anthropic-messages` | Anthropic の Messages API と互換エンドポイント |

**プリセット。** 既知の 16 サービスから 1 つを選ぶと、あとは API キーを入力するだけ
です。プリセットが名前・ベース URL・プロトコルの 3 つをすべて確定するため、フォーム
はその行を省きます。Anthropic、OpenAI、Google Gemini、DeepSeek、Groq、Mistral、
Moonshot、xAI、Z.ai、OpenRouter、MiniMax、Qwen、そしてそのうち 4 社が別途運営する
中国本土向けサイト。各オプションは到達先のホストを明示します。ベンダーの 2 つの
サービスを見分けるのはそれだからです。

**カスタム**はリストの先頭にあり、新しいフォームが開く場所です。プリセットの
エンドポイントを引き継ぐ方法でもあります。カスタムに切り替えると 3 行が戻り、
プリセットが入れた値を保持したまま編集できます。カスタムの行にプリセット自身の
URL を入力するとそのプリセットが選択され、そこから編集して外れるとカスタムに戻り
ます。ラベルがフォームの保持していないエンドポイントを表すことは決してありません。
プリセットを選んでもあなたのキーには一切触れません。

モデル ID はエンドポイント自身が一覧化を実装している場所で提案されます。何を受け
入れるかについては、このプラグインが同梱できるどんなものよりも、あなた自身のサーバー
のほうが信頼できる権威であり、プライベートゲートウェイを知る唯一の存在です。この
フィールドはどちらの場合でも入力した任意の ID を受け付けます。

**機能の提案。** 既知のモデル ID に対して、フォームは画像入力を受け付けるか、
コンテキストウィンドウ、最大出力を、追跡対象の全プロバイダーを網羅するライブの
[models.dev](https://models.dev) インデックスから補完します。手動で設定した値は
提案より優先され、再び上書きされることはありません。インデックスに到達できない
場合でも、すべてのコントロールに実用的な既定値があります。

**接続テスト**は、プロバイダーリクエスト用に選択したトランスポートを通じて
エンドポイントを検査します。都合のよい代替ではなく、チャットが実際に通るのと
同じチャネルです。`fetch` で通過するのにチャットは `requestUrl` を通る、という
テストは間違ったものをテストしていることになります。

**プロンプトキャッシュ**は、プロバイダーがプロンプトの不変部分（システム指示、
ツール定義、スキル、開いているノート）をどれだけ長く保持できるかを決めます。
これにより、後続のリクエストは全額ではなくおよそ 10 分の 1 の価格で読み戻せます。

既定は **1 時間**で、これは基盤となるエージェントライブラリの既定とは意図的に
異なります。5 分はターンが数秒間隔で届くターミナルエージェントには適した長さです
が、2 つの質問の間に書き物をする 10 分の間に期限切れになり、プロンプト全体が改めて
課金されます。1 時間は保存コストが高く（Anthropic は 5 分キャッシュ書き込みの
基本入力 1.25 倍に対し、1 時間キャッシュ書き込みには 2 倍を課金）、2 回目の後続
リクエストがそのプレミアムを回収します。セッションが本当に 1 質問分しかないなら
**5 分**を、キャッシュマーカーを拒否するエンドポイントには **オフ**を選んでください。

プロバイダーはこの設定を対応可能なものにマップし、対応しないものは無視するため、
ここでの設定はどのモデルを選んだかに依存しません。**エージェントの詳細を表示**を
オンにすると、コンテキストリングのポップオーバーが、プロバイダーが報告する限り
1 時間レートで書き込まれたシェアを表示します。これが設定が効いた唯一の証拠です。
無視するプロバイダーは単に安い方で課金するだけだからです。

## Chat

上に動作、下にストレージ。

ここではスイッチなしで 2 つのことが起こり、どちらも知っておく価値があります。
開いているノートは**すべて**のターンに注入されます。パスと本文の両方です。ですから
「今見ているノート」と言う必要はありません。そしてコンテキストウィンドウが埋まると、
会話は自ら整理します。コマンドパレットの *以前の思考を整理* は同じことを手動で行い、
トランスクリプトは各整理を、そこで書いた要約を開いて読める継ぎ目として記録します。

- **エージェントの詳細を表示** — チャットパネルにトークン数、支出、生のツール引数を
  表示します。既定はオフ。エージェントが実際に送ったものを見たいときにオンにします。
- **ツール活動を開く** — マシントラフィックのどれだけを開いた状態で始めるか。
  思考、ツール呼び出し、結果。すべて既定では折りたたまれ、どの行も手動で開けます。
  そのモードでは、連続する 2 つ以上の思考とツール呼び出しが、実行内容を述べる 1 つの
  行にまとまります（「ノートを読んで考え抜いた」）。元の行は順序どおり内側にあります。
  失敗した呼び出しと回答済みの質問は折りたたみの外に残ります。どちらも見るために
  クリックを費やすべきではないからです。
- **返信中の送信** — Piem がまだ答えている間に送ったメッセージは拒否されません。
  待機し、これがその長さです。*回答全体が終わったとき*が既定で安全な選択です。返信は
  計画を完了し、それからあなたのメッセージが次の質問として読まれます。*現在の
  リクエストが終わったとき*はより早く、メッセージはこのターンのツールの後、Piem が
  再び話す前に着地し、長いツール呼び出しの連続を途中で方向転換できます。どちらの
  設定も割り込みはしません。待機中のメッセージの**送信**アクションがそれを行い、
  返信を打ち切って 1 つのメッセージを今すぐ送ります。
- **コンテキスト整理** — 会話がいつ要約されて余地を作るかを決める予約・保持予算。
  Piem はモデルに設定したコンテキストウィンドウに対して計画します。
- **保持するチャット数** — 保持上限。上限を超えて新しいチャットを始めると、最も古い
  ものがゴミ箱へ移動します。無制限に設定すると何もゴミ箱に入りません。
- セッションディレクトリがここに表示され、どのフォルダにトランスクリプトがあるか
  常に分かります。

## Extensions

MCP サーバー、スキルのインポート、組み込みスキルファイル。**組み込みスキル
ファイル**は準備状況とローカル変更のために保持されたファイルを表示します。
**準備を再試行**は失敗したダウンロードを再試行し、**欠落ファイルを復元**は編集を
上書きせずに削除された組み込みエントリを復元します。**再読み込み**はローカルスキル
を読み直します。パス、優先順位、更新ルールについては [Piem を拡張する](extending.ja.md)
を参照してください。

**エラーレポートとパフォーマンスデータを共有**は既定でオンです。モデル名とツール名、
使用状況、タイミング、エラーを Piem のメンテナーの `https://otlppiem.shangxin.me`
に送信します。オフにすると新しいレポートが直ちに停止し、未送信データは破棄され
ます。すでに送信されたリクエストは呼び戻せません。再度オンにした後は、**設定 →
コミュニティプラグイン**で **Piem を再読み込み**して共有を再開してください。宛先は
固定で、設定では編集できません。ゲートウェイ認証はすでに構成済みなので、アカウント
やコレクターの資格情報は不要です。

同梱された元の [b1tank/pi-otel](https://github.com/b1tank/pi-otel) 拡張は、
`/v1/traces`、`/v1/metrics`、`/v1/logs` で OTLP/HTTP JSON を使用します。メトリクスは
60 秒ごとにエクスポートされ、トレースとログは別々にバッチ処理されます。コンテンツ
キャプチャはオフのままですが、モデルのエラーテキストにはノートの内容が含まれる
場合があります。[データ開示](security.ja.md#opentelemetry-の送信) を参照して
ください。これは完全なサブエージェントのトレースを提供したり、遅いシャットダウン中に
最後のバッチが届くことを保証したりはしません。

## General

- **言語** — 英語または簡体中文。既定では Obsidian 自身の言語に従います。ここでの
  上書きは、プラグインをアプリとは別の言語にしたいときのためのものです。
- **送信ショートカット** — 送信に `Enter`、または `Enter` で改行を挿入しつつ
  `Ctrl`/`⌘`+`Enter` で送信。すでに身についた指の記憶に合う方を選んでください。
- **ログレベル**と**ログビューア** — ログビューは独自のリーフとして開き、プロバイダー
  が誤動作したときに最初に見る場所です。
- **バージョン情報** — 実行中のバージョン（`manifest.json` から読み取り、決して
  言い直さない）、リンク、vault から出ていくものの要約、そしてこのデバイスでキーが
  どう保存されるか。

## Commands

Piem がコマンドパレットに追加するすべて。*Piem: …* として表示されます。

| コマンド | 機能 |
| --- | --- |
| Open chat | チャットサイドパネルを開く |
| Open log view | ログリーフを開く |
| New chat | 新しい会話を始める |
| Stop response | 進行中のターンを中止する |
| Tidy earlier thoughts | 会話を手動で圧縮する |
| Focus chat input | カーソルをコンポーザーへ移す |
| Ask about selection | 選択したテキストとノートパスを下書きに追加する |
| Ask about this note | 現在のノートのパスを下書きに追加する |

すべて **設定 → ホットキー**で独自のホットキーに割り当てられます。

### コンテキストメニューから尋ねる

Obsidian のファイルメニューで **Ask about this file**、**Ask about this folder**、
**Ask about these items** を使います。エディタはテキストが選択されているときに
**Ask about selection** を、そうでなければ **Ask about this note** を提供します。
外部の HTTP/HTTPS リンクは **Ask about this link** を提供します。

各アクションは、質問の上、テキスト入力フレーム内に展開可能な参照カードを追加します。
カードとテキストは 1 つのフォーカスフレームを共有します。カードを展開すると、
その完全なパス、URL、キャプチャした選択を確認できます。取り除くと次の質問から
外れます。あなた自身の言葉は変わりません。質問の準備ができたら **送信**を選びます。
メニューを開いたりカードを追加したりしても、ウェブページを取得したりモデル
リクエストを開始したりはしません。

カードは下書きに属し、パネルを閉じたりチャットを切り替えたりしても残ります。
最初のスキルまたは参照カードが新しいチャットの識別を保存するため、その未送信の
下書きは Obsidian を再起動した後も到達可能です。手を付けていない空白のチャットを
開いても何も保存されません。カードはキューに入った質問とともに移動し、キューの
質問を取り戻すと戻り、送信された質問のバブル内に、スキルコンテンツと同じ開示スタイル
で現れます。スキルを選択するか、既知の `/skill:name` コマンドをスペースで補完すると、
テキスト入力内の同じ展開可能なカードになります。テキスト領域にはあなたの質問だけが
残ります。スキルカードを取り除くと呼び出しが取り除かれ、質問と他の参照は残ります。
保存された下書きは、送信されるカードとスキルの信頼できる情報源のままであり、この
グループ化は会話を再読み込みしても残ります。Pi のネイティブなカスタムメッセージは、
モデル向けの参照テキストとカード向けの別のメタデータを保存します。ファイルとフォルダ
のカードはパスを示します。全内容がすでに読まれたと主張するものではありません。選択
カードは選択時のままの一節を保持します。

1 つの下書きは最大 64 の参照と 20,000 文字の参照データを受け付けます。下書きテキスト
は既存の永続化上限を保ちます。最初の 20,000 文字が保存され、開いたエディタは全文を
保持します。繰り返された参照はマージされます。予算超過の追加は説明とともに拒否され、
利用できない項目は報告されます。長い選択は 2,000 Unicode 文字に切り詰められ、通知が
出ます。別の **ピン**コントロールは今も最大 8 個の恒久的なファイル参照をサポート
します。1 質問分のカードを追加してもピンを消費しません。

保存された下書きが読み込まれる間、入力は読み取り専用のままです。モバイルでは、参照
を追加すると折りたたまれた入力が開き、質問にフォーカスします。送信後、`web_fetch` は
リンクされたページを要求できます。サイトのアクセス制限とツールのテキスト上限に従い
ます。アクティブなノートの開いたエディタは、未保存の編集を含む最新のテキストを供給
します。閉じたノートは vault のコピーを使います。メニューの利用可否は Obsidian に
従うため、カスタムビューやモバイルのジェスチャーは異なるエントリを露出する場合が
あります。

## Storage

セッションは `<vault config dir>/plugins/piem/sessions/` 下の JSONL ファイルで、
pi 互換のバージョン 3 ヘッダーとツリー状のエントリ（`id` / `parentId`）で書き込まれ
ます。pi が使うのと同じ形なので、トランスクリプトはこのプラグインに閉じ込められません。

未送信の下書きテキストと参照カードは、ログの隣にある会話ごとの
`drafts/<session-id>.json` ファイルに存在します。パネルを閉じても両方が保存され、
古いテキストのみの下書きも読めるままです。

ステージングされた画像は**決して**永続化されません。セッションログはバイトの代わりに
プレースホルダーを保存するため、同期する vault があなたのスクリーンショットを持ち
運ぶことはありません。

## Versions

実行中のバージョンは `manifest.json` にあり、**バージョン情報**に表示されます。
リリース済みのバージョンと、それぞれが必要とする最小 Obsidian バージョンは
[`versions.json`](../versions.json) に一覧されています。
