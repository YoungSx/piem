# 扩展 Piem

[← 回到 README](../README.zh-CN.md) · [English](extending.md)

给 Piem 加东西有两条路：**技能**，是它能遵循的指令；**MCP 服务器**，是它能调
用的工具。

## 技能

技能是一段可复用的指令，代理能遵循它，你也能在输入框敲 `/` 直接调用。
Piem 按以下顺序合并三处技能，后面的同名技能覆盖前面的：

1. **内置** —— `Piem/builtin-skills/<名字>/SKILL.md` 中的标准文件。包含
   `summarize`、`link-graph`、`tag-organize`、`find-skills`、
   `efficient-web-research`、`vault-memory` 和 `distill-skill`。
2. **用户级** —— 桌面端的 `~/.pi/agent/skills`、`~/.agents/skills`，以及设置中
   可选的额外目录。这些目录内部仍沿用现有优先级。
3. **笔记库** —— `Piem/skills/<名字>/SKILL.md` 中自己写的或导入的技能。
   笔记库里的同名技能优先于另外两处。

`vault-memory` 教代理回顾和自主维护有用事实；`distill-skill` 教它将已验证且
有复用价值的流程保存为仓库技能。流程规则全部在 `SKILL.md` 中，使用普通仓库
文件工具。成功一次即可考虑保存，无需逐份草案再审批。
代理优先完善已有技能，避免近似重复，并原地替换被用户纠正的旧步骤。未经验证
的尝试留作带日期的观察，不冒充已跑通的流程。新增和修改的技能在下一用户轮
加载；保存技能本身不会执行它。
详见[记忆与过往对话](tools.zh-CN.md#记忆与过往对话)。

### 内置文件与更新

Piem 从与当前插件版本匹配的 GitHub Release 下载内置 Markdown 资源，校验插件
中记录的摘要后，在笔记库中创建真实文件。目录在 Obsidian 里可见，可以像其他
笔记一样打开、搜索、同步。描述直接来自技能文件，因此自带的英文描述不会随
界面语言切换。

**首次安装需要连接 GitHub。** 工作区就绪后开始准备，不会阻止聊天。下载失败
时，已有技能仍可离线使用。**设置 → Piem → 扩展能力 → 内置技能文件** 显示
结果，并提供 **重试准备**。后台不会循环重试，普通消息也不会触发下载。

更新只替换与安装记录仍一致的文件。你改过的文件和原先已有的文件都会保留，
冲突列在设置中。删除一个内置技能后，它会保持移除；**恢复缺失文件** 可以重新
创建缺失文件，但不会覆盖你的修改，也不会重新启用已关闭的技能。当前版本不再
提供的文件会留下供你查看。同步与更新不是跨设备事务；所有权证据不一致时，
保留文件而不覆盖。

需要定制某个默认技能时，把它的文件夹复制到 `Piem/skills/`，保留相同技能名。
你的副本优先，官方版本仍可更新。内置资源只包含 Markdown，不安装或执行脚本。
下载涉及的数据说明见[安全与隐私](security.zh-CN.md)。

### 写一个

一份 `SKILL.md` 需要两个 frontmatter 字段：

```markdown
---
name: weekly-review
description: 收集本周的日记笔记，据此起草一份周复盘。
---

读最近七天的每篇日记笔记。把标了 #decision 或 #blocked 的内容挑出来。用
Templates/Weekly.md 的模板，在 Reviews/ 下起草一份复盘。
```

- `name` —— 只能是小写字母、数字和连字符，并且必须与所在目录同名。
- `description` —— 模型在判断这个技能是否适用时读的就是它。写给模型看，不是
  写给自己看。

Piem 使用 Pi 的技能加载器和提示词格式化器，采用
[Agent Skills 格式](https://agentskills.io/specification)。模型先看到技能名称、
描述和位置组成的目录；需要某项技能时，调用 `read_skill` 获取正文，你输入
`/名字` 也能直接提供正文。引用文件再按需单独读取。这就是
**渐进式披露**：程序把正文缓存到内存，不代表把全部正文都放进模型上下文。

每个新的用户轮开始前会重新读取技能：改一个、加一个，**下一条消息**就生效，
不用重载插件。已关闭的技能会被排除；`disable-model-invocation: true` 会把技能
从模型目录中隐藏，但仍可显式调用。

`read_skill` 每页最多提供 50 KiB，并告诉模型如何续读，不会切坏字符。
续读携带内容指纹：文件变了就从头读取，避免混用两个版本。同一工具也能按技能
名和相对路径读取引用的 UTF-8 文本，包括桌面端的用户级技能。资源必须位于该
技能目录内，不包含隐藏路径段，单文件不超过 1 MiB；符号链接也不能越界。
笔记库中的图片仍可通过 `read` 读取。Piem 不提供运行技能脚本的 shell。

通过 `read_skill` 或 `/名字` 加载过的指令会在对话压缩后保留原文，包括读过的
引用页。重复页只保留一份，新加载的版本替换先前保留的旧版；子代理和重新打开
的聊天也适用，界面不会重复显示这些保留副本。未激活的技能仍只提供目录信息。

在 **扩展能力** 中，徽章显示 **内置**、**全局** 或 **笔记库**。内置和笔记库
文件有 **打开** 按钮；导入的笔记库技能还保留来源 URL、更新和删除操作。问题
列在对应来源旁。**重新加载** 只重读本地文件，不下载或恢复文件。文件夹搜索
报告区分空目录、缺失目录和无法读取的目录。正在回答的对话会保留当前技能快照，
下一条消息再使用更新后的内容。

### 从 GitHub 导入

**设置 → Piem → Extensions** 支持直接从 GitHub URL 导入技能：选一个仓库或子
目录，先看计划，然后 Piem 把那些 `SKILL.md` 写进 `Piem/skills/`，同时留一份
出处记录（provenance sidecar）。**Update** 按钮日后能重新抓取，靠的就是那份
记录。

文件夹 URL 会一起导入 `SKILL.md` 和 Markdown 引用，指向单个技能或技能集合
都适用。单文件 URL 只导入那一个文件。脚本等非 Markdown 文件会在下载前跳过。
每次最多导入 10 个技能、40 个 Markdown 文件，单文件最多 256 KiB；超限会报错，
不会悄悄丢掉 Markdown 资源。写入失败也会如实报告，不宣称安装成功。

旧版通过单个文件夹导入、但缺少引用的技能，可以选择 **Update** 补齐。即使远端
目录没有变化，Piem 也会核对文件集合，并保留原来的安装目录；本地修改仍会产生
冲突提示。

## 提示模板

提示模板放在仓库里的 `Piem/prompts`，出现在同一套 `/` 自动补全里，并标注来
源。

如果一个模板和一个技能同名，模板优先，技能仍可通过 `/skill:名字` 访问。在自
动补全里选中它时，会自动插入那个消歧形式。

## MCP 服务器

Piem 通过 Streamable HTTP 连接远程 MCP（Model Context Protocol）服务器，把它
们的工具并入代理自己的工具表。在 **设置 → Piem → Extensions** 里配置：每个服
务器是一个 http(s) URL、一个可选的 Bearer 令牌，和一个启用开关。

- 工具对模型呈现为 `mcp_<服务器>_<工具>`，任何一份对话记录里都能分清远程工具
  和仓库工具。与已有工具重名时用数字后缀消歧。
- 服务器名称旁的徽章显示 **已连接** 及工具数、**连接中**、**连接失败**、
  **待连接** 或 **已停用**。开关决定是否启用，徽章说明实际连接结果；错误原文
  保留在名称下方。
- 保存设置会连接已启用的服务器，尚未打开聊天时也一样。URL 和令牌都没变的已
  连接服务器保持不动；改过的或失败过的会重新连接。待连接行旁有 **连接** 按钮，
  失败行旁有 **重试连接** 按钮，可立即再试。发送新消息也会刷新工具表；后台不
  会定时重试。
- 服务器编辑器里的 **测试** 按钮探测草稿配置，不必先保存。
- Bearer 令牌与服务商 API 密钥走同一套落盘密封生命周期。见
  [安全与隐私](security.zh-CN.md#你的密钥存在哪)。
- 超时是有界的：连接并列出工具 15 秒，单次工具调用 120 秒，工具输出按与其他
  工具相同的字节预算截断。

### 为什么只支持远程

不支持 stdio 传输。它要拉起子进程，而这在手机上是禁区——这个插件在手机上是一
等公民，不是事后想起来的补丁。一个在手机上不可能存在的能力，宁可对所有人都
不做，也不做成桌面端的意外惊喜。

也没有 OAuth 流程。一个静态 Bearer 令牌足以覆盖一个个人仓库现实中会对话的那
些服务器，而它替掉的那套流程需要一次浏览器往返——Obsidian 并不适合承载它。

## 开发内置技能

仓库中的 `skills/<名字>/SKILL.md` 是内容的唯一来源。新增带 `name` 和
`description` 文件头的合法目录，构建就会自动发现，无需往 TypeScript 登记。
Markdown 引用和模板会保留相对路径，随技能一起分发。构建会拒绝缺失元信息、
不安全路径、脚本、符号链接和不存在的链接资源。

`npm run build` 生成 `dist/builtin-skills.json`，并把摘要写入 `main.js`；
`npm run check:skills` 检查两者与源文件是否一致。发布流程将资源与三个标准
插件文件一起上传，并生成来源证明。

`npm run dev` 会监视新增、修改和删除，并在 `main.js` 旁生成相同 JSON。
把这两个文件复制到开发用插件目录后重载 Piem；开发构建读取本地 JSON，不需要
先发布 Release。正式构建始终下载与已安装版本匹配的资源。
