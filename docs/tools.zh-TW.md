# 代理的工具

[← 回到 README](../README.zh-TW.md) · [English](tools.md) · [简体中文](tools.zh-CN.md) · [日本語](tools.ja.md)

Piem 對你儲存庫做的每一件事，都經由下面某個工具。沒有暗管：只要有改動發生，
就一定有一次工具呼叫促成了它，而那次呼叫就在對話記錄裡。

工具接受的每一個路徑都**相對儲存庫根目錄**。絕對路徑和 `..` 逃逸會被拒絕，外
掛自己的目錄（`.obsidian/plugins/piem`）預設禁止存取——代理沒法在對話中途重
寫自己。

設定目錄**唯讀，不可寫**。Obsidian 的索引不收錄 `.obsidian/`——那個目錄對檔案
瀏覽器、搜尋和儲存庫 API 都是隱形的——所以 `ls` 和 `read` 會退回檔案系統去搆它。
代理可以列出你的設定、快速鍵、工作區配置，以及每個已安裝外掛的 manifest 和
`data.json`，並回答關於它們的問題。`.obsidian/` 底下沒有任何東西能被代理寫入、
編輯、移動或刪除。

## 模型選擇

`switch_model` 查詢、搜尋和切換已有 API 金鑰的模型。切換在呼叫它的對話中，
從下一次請求起生效，並儲存預設選擇；新服務商會收到該對話。上游顯示零價格
代表未知。詳見[內建 Pi 擴充](extending.zh-TW.md#內建-pi-擴充)。

## 檔案

`read` · `write` · `edit` · `ls` · `find` · `grep` · `move_note` · `trash_note`

`read`、`write`、`edit` 是 pi 自己的 harness 工具，跑在一個儲存庫執行環境上，
所以行為跟在 pi 裡一致：`edit` 做精確取代，每段 `oldText` 必須恰好匹配一次。
差一點點就是一次失敗的呼叫，不是一次猜測。

`trash_note` 走 Obsidian 的垃圾桶，所以這裡的刪除跟你在儲存庫裡的任何刪除一樣
可復原。

## 筆記與 Obsidian

`get_active_note` —— 你正在看的那篇筆記，可選帶上你的選取範圍或全文。

`get_note_links` / `get_note_metadata` —— 用 Obsidian 自己的中繼資料快取讀連
結、反向連結、標籤、frontmatter。代理讀的是圖譜檢視讀的那份索引，而不是重新解析
檔案。

`update_frontmatter` —— 經 Obsidian 的檔案管理員原子改寫 YAML 標頭。在把一百
篇筆記交出去之前值得知道一件事：標頭會被整體重新序列化，所以鍵順序可能變，
裡面的註解會遺失。

`open_note` · `open_side_panel` · `insert_at_cursor` · `goto_location` ——
代理能驅動編輯器，不只是操作檔案。

`notify` —— 一條 Notice，用在你走開的時候某件事做完了。

`ask_user` —— 代理需要你拍板時給出可選答案，比如確認你說的是兩篇筆記裡的哪
一篇。問題顯示在發問的對話裡，子代理的問題也歸在同一對話。切換聊天後，問題
留在原對話等你，各個對話獨立排隊。聊天面板已開啟但被隱藏或收合時，問題改用
對話框顯示，所有對話合計一次只彈一個。沒有開啟聊天面板時，代理改在對話正文裡
提問。

## 任務

`list_tasks` · `summarize_tasks`

全儲存庫的任務核取方塊。這就是「我六月份說過要做什麼」變得可回答的原因。

## 網路

`web_search` —— 複用目前模型服務商的憑證搜尋資料。介面需支援 OpenAI Responses
或 Anthropic Messages 原生搜尋。查詢和指定網址發給該服務商；不支援時明確
報錯，不會靜默切換服務商。搜尋可能額外計費，來源保存在工具結果中，並交給
下一輪模型請求。

`web_fetch` —— 讀取已知網址，始終可用。它固定走 `requestUrl` 傳輸，和 Piem
裡其他網路呼叫同屬一層出口，出網行為集中在一處可查——而且普通網頁也抓得到，
換 `fetch` 傳輸會被 CORS 攔下。`requestUrl` 與 `fetch` 的設定只影響 token 是否
串流。

要用你存在 Obsidian 鑰匙圈裡的憑證給請求驗證，agent 會把佔位符
`{{secret:<條目-id>}}` 寫進網址、某個請求標頭的值或請求主體裡——比如一個
`Authorization` 標頭寫成 `Bearer {{secret:my-api-token}}`，其中 `my-api-token`
就是你在 **設定 → 外掛的鑰匙圈** 裡給這個條目起的 id。值在請求離開儲存庫
的前一刻才被查出並填入，所以它不會進入對話：聊天記錄裡留的是佔位符，
模型從未看到憑證本身，也沒有任何工具會把金鑰以明文回傳。agent 可以
按 id 引用任意條目——沒有白名單——而一個沒有對應條目的佔位符會直接讓
呼叫失敗（報出的是 id，那只是個標籤，不是金鑰），而不是發一個空憑證出去。
有一點它攔不住：如果你存取的伺服器把憑證在回應裡回顯回來，那份回應是
模型要讀的——佔位符只把金鑰擋在 agent *寫的* 東西外，擋不住伺服器選擇發
回來的東西。

## 對話檢查點

`context_checkpoint` 儲存命名的歷史位置，`context_timeline` 展示目前路徑、檢查點
與摘要。`context_compact` 從較早位置儲存摘要分支，再請求模型繼續。舊歷史仍在
聊天檔案中，不回滾筆記或外部操作。詳見[內建 Pi 擴充](extending.zh-TW.md#內建-pi-擴充)。

## 技能

`read_skill` —— 按需回傳已載入的技能內容，包括 `Piem/builtin-skills/` 中的內建檔案。見
[擴充 Piem](extending.zh-TW.md)。

## 記憶與過往對話

`vault-memory` 是一個技能：召回、儲存、修正和晉升規則都在它的 `SKILL.md` 中。
它使用現有的 `find`、`ls`、`grep`、`read`、`write`、`edit`，維護 `Piem/memory/`
裡的普通 Markdown。

技能指引代理在實質任務開始時回顧相關記憶。`MEMORY.md` 儲存簡短的目前事實；
帶日期的日誌儲存暫時或尚不確定的觀察。明確的長期偏好、使用者修正和已驗證的
有效經驗，出現一次即可儲存。新的修正取代同一範圍內的舊值，不用跨天湊次數，
也不用逐條審批。可重複使用的流程交給 `distill-skill` 儲存。

代理先讀已有內容，再精確取代需要修改的部分，保留無關文字。`write` 用來建立
缺失檔案；它會覆寫已有檔案，因此技能不把它當作附加工具。這些是基於普通檔案
工具的技能指引，沒有獨立的記憶引擎。復原依靠你儲存庫的檔案復原或版本控制，
Piem 不額外提供記憶備份庫或跨裝置交易。刪除目前事實不會抹除每日日誌或來源聊天。

召回經由可見的工具呼叫完成，沒有自動注入記憶正文、背景複盤程序、額外模型或
向量資料庫。目前要求優先於舊偏好。筆記和對話摘錄只是歷史情境，裡面引用的
命令不會自動獲得執行權限。過往聊天仍可透過現有聊天歷史和搜尋查看。

## 委派

`spawn_subagent` · `wait_subagent` · `list_subagents` · `kill_subagent` ·
`follow_up_subagent` —— 見下面的[子代理](#子代理)。

## MCP

已連線的 MCP 伺服器每暴露一個工具，就產生一條 `mcp_<伺服器>_<工具>`。這個前
綴是刻意的：任何一份對話記錄裡，你都能一眼分清遠端工具和儲存庫工具。見
[MCP 伺服器](extending.zh-TW.md#mcp-伺服器)。

每個 MCP 工具的描述都會交代自己的來處，所以模型也知道：呼叫它意味著把參數發
到你儲存庫之外、Obsidian 之外的一台伺服器。

## 子代理

`spawn_subagent` 啟動一個自成體系的任務並立即回傳它的 id；`wait_subagent`
收取報告。`list_subagents` 不用等待就能說出每一個現在到哪一步了，
`kill_subagent` 停掉答案已經不需要的那個，`follow_up_subagent` 給已經停下來的
那個再下一條指令。

子代理在行程內執行，用與父代理相同的模型和傳輸方式，但對話記錄隔離在記憶體
裡——它做的一切都不會進入對話日誌。它唯一的輸出，就是父代理作為工具結果讀到
的那份報告。同時發起的多個 spawn 並行執行。

任務可以在三種角色下委派：

| 角色 | 用來做什麼 | 回來的是什麼 |
| --- | --- | --- |
| `general` | 任何自成體系的任務 | 任務產出的東西 |
| `scout` | 一次調研掃蕩 | 只有發現；儲存庫保持原樣 |
| `reviewer` | 一次審稿 | 一份評估，不是修改 |

子代理繼承完整的儲存庫工具集和你的技能，並且可以再往下衍生一層——但不能更深。
層級樹封頂於 父 → 子 → 孫，是**構造上的**封頂，不是靠一句檢查：孫代理的工具
集裡根本就沒有 spawn 工具。

等待視窗到期只意味著「還沒做完」，絕不是一次終止。子代理在兩次等待之間繼續
幹活。你也可以自己在子代理面板裡停掉某次執行——停了之後父代理會被告知，而且
不會把你停掉的東西再拉起來。

已經停下來的子代理可以再接一條指令，還是同一個 id、同一份對話記錄：可以是就
它剛給的報告再追問一句，也可以是讓半途崩掉的任務再來一次。失敗的子代理會保留
它已經弄明白的一切，所以把它撿回來只需要一條指令，而不是整個任務重做一遍——
這就是斷網從「致命」變成「可復原」的地方。它依然看不到你的對話，指令也依然是
Piem 下的，不是你下的。

執行結束之後，面板上的**封存已結束的**會把所有已結束的執行收進收合起來的
**已封存**裡。這是整理，不是刪除：它們在那兒照樣能翻出來讀，而代理自己的工具
完全察覺不到差別——一份你讀完收起來的報告，它照樣收得到。

## 代理做不到的事

- 執行 shell 命令。任何平台上都沒有 shell 工具。
- 伸到你儲存庫外面去——除了 `web_fetch` 和模型服務商本身。
- 讀寫它自己的外掛目錄。
- 衍生第四層子代理。
- 請你批准一次 `write` 或 `edit`——沒有這一步。見
  [安全與隱私](security.zh-TW.md#沒有確認步驟)。
