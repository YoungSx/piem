# Piem を拡張する

[← README に戻る](../README.ja.md) · [English](extending.md) · [简体中文](extending.zh-CN.md) · [繁體中文](extending.zh-TW.md)

Piem に新しいことを教える方法は二つあります：**スキル**（それが従える指示）
と、**MCP サーバー**（それが呼べるツール）です。

## スキル

スキルは、エージェントが従える再利用可能な指示で、コンポーザーで `/` を入力
して呼び出せます。Piem は三つのソースをこの順で組み合わせ、後のソースが同名
の先のスキルを上書きします：

1. **組み込み** —— `Piem/builtin-skills/<名前>/SKILL.md` 配下の標準ファイル。
   `summarize`、`link-graph`、`tag-organize`、`find-skills`、
   `efficient-web-research`、`vault-memory`、`distill-skill`、
   `mineru-parse`、`build-knowledge-base` を含みます。
2. **ユーザーレベル** —— デスクトップでは `~/.pi/agent/skills` と
   `~/.agents/skills`、それに設定内の任意の追加ディレクトリ。これらはユーザー
   レベルのソース内で既存の優先順位を保ちます。
3. **ボールト** —— `Piem/skills/<名前>/SKILL.md` 配下の、自作または取り込んだ
   ファイル。ボールトのスキルは他の二つのソースの両方を上書きします。

`vault-memory` は有用な事実の想起と自律的な保守を教え、`distill-skill` は有用
で検証済みの手順をボールトスキルとして保存することを教えます。それらのワーク
フローは丸ごと `SKILL.md` にあり、普通のボールトファイルツールを使います。一
度の成功した実行で十分なことがあります。エージェントは各下書きの承認をあなた
に求めることなくスキルを作成・改善でき、ほぼ重複するものより既存のスキルを好
みます。新しいユーザーの訂正は古くなった手順をその場で置き換えます。検証され
ていない試みは、跑通したと主張されるレシピではなく、日付付きの観察のままにと
どまります。新規・編集されたスキルは次のユーザーターンで読み込まれます。保存
は実行を意味しません。
[メモリと過去の会話](tools.ja.md#記憶と過去の会話)を参照。

### 組み込みファイルと更新

Piem は、インストールされたバージョンに一致する GitHub リリースから組み込み
Markdown リソースをダウンロードし、プラグインに固定されたチェックサムを検証
して、あなたのボールトに実ファイルを作成します。フォルダは Obsidian で見え
ます：他のノートと同じように開き、検索し、同期できます。説明は各ファイルから
来るので、同梱の英語の説明はインターフェース言語では変わりません。

**初回のインストールには GitHub への接続が必要です。** 準備はワークスペースが
整った後に走り、チャットをブロックしません。ダウンロードが失敗しても既存の
スキルはオフラインで使えます。**設定 → Piem → 拡張機能 → 組み込みスキル
ファイル** が結果を示し、**準備を再試行** を提供します。バックグラウンドの
再試行ループは作らず、普通のメッセージがダウンロードを引き起こすことは決して
ありません。

更新は、記録されたインストール済みの内容と今も一致するファイルだけを置き換え
ます。あなたの編集と既存のファイルは保たれ、衝突があれば設定に一覧されます。
組み込みスキルを削除するとそれは削除されたままになります。**欠けている
ファイルを復元** は、編集済みのものを上書きしたり無効化されたスキルを再度
有効にしたりせずに、欠けているファイルを作り直します。リリースで引退した
ファイルはあなたが見直せるように保たれます。同期と更新の操作はクロスデバイス
のトランザクションではありません。所有権の証拠が一貫しないときは、上書きせず
ファイルを保存します。

既定を客製しつつ公式の更新を受け取り続けるには、そのフォルダを `Piem/skills/`
にコピーし、同じスキル名を保ちます。あなたのコピーが優先されます。組み込み
スキルリソースは Markdown のみを含み、スクリプトのインストールや実行はしませ
ん。ダウンロードの開示は[セキュリティとプライバシー](security.ja.md)を参照。

### 一つ書く

`SKILL.md` には二つのフィールドを持つ frontmatter が必要です：

```markdown
---
name: weekly-review
description: その週の日次ノートを集め、そこからレビューの下書きを作ります。
---

過去 7 日間のすべての日次ノートを読む。#decision または #blocked のタグが
付いたものを抜き出す。Templates/Weekly.md のテンプレートを使って Reviews/ に
レビューの下書きを作る。
```

- `name` —— 小文字、数字、ハイフンのみで、フォルダ名と一致しなければなりません。
- `description` —— スキルが適用されるか判断するときにモデルが読むもの。自分の
  ためではなく、モデルのために書いてください。

Piem は [Agent Skills フォーマット](https://agentskills.io/specification)のため
に Pi のスキルローダーとプロンプトフォーマッターを使います。モデルはまずスキル
名、説明、場所のカタログを見ます。一つが適用されると、指示のために `read_skill`
を呼びます。`/name` と入力すると直接それらを提供します。参照されたファイルは
必要なときに別途読まれます。これが**漸進的開示**です：スキル本文をメモリに
キャッシュしても、それらすべてがモデルのコンテキストに加わるわけではありませ
ん。

スキルは新しいユーザーターンごとにディスクから読み直されます：一つを編集・追加
すると**次のメッセージ**で効き、プラグインの再読み込みは要りません。無効化され
たスキルは除外されます。`disable-model-invocation: true` は、明示的な呼び出しは
使えるまま、スキルをモデルのカタログから隠します。

`read_skill` は 1 ページあたり最大 50 KiB を返し、文字を分割せずに続ける方法を
モデルに伝えます。継続はコンテンツの指紋を持ちます：ファイルが変わっていれば、
二つのバージョンを混ぜる代わりにモデルは最初からやり直します。同じツールが、
スキル名と相対パスで参照された UTF-8 テキストファイルを読みます。デスクトップ
のユーザーレベルスキルも含みます。リソースはそのスキルのディレクトリ内に留ま
り、隠しパスセグメントを含まず、最大 1 MiB でなければなりません。シンボリック
リンクはディレクトリから逃げられません。ボールトの画像は `read` で引き続き
利用できます。Piem は同梱スクリプトのためのシェルを提供しません。

`read_skill` や `/name` を通じて既に読み込まれた指示は、読み込まれた参照ページ
を含め、会話の圧縮を越えて一字一句そのまま生き残ります。繰り返されたページは
一度だけ保たれ、新しく読み込まれたバージョンが以前保持されたコピーを置き換え
ます。これはサブエージェントや再度開かれたチャットでも働きます。保存された
コピーは重複したチャット行を追加しません。有効化されていないスキルは依然として
カタログエントリだけを提供します。

**拡張機能** では、バッジが **組み込み**、**グローバル**、または **ボールト**
を示します。組み込みとボールトのファイルには **開く** ボタンがあり、取り込ま
れたボールトスキルはソース URL と更新／削除のコントロールも保ちます。問題は
関連するソースの横に現れます。**再読み込み** はローカルファイルを読み直します。
ダウンロードや復元はしません。フォルダの検索レポートは、空・欠落・読み取り
不能のフォルダを区別します。実行中の会話は、次のメッセージまで現在のスキル
スナップショットを保ちます。

### GitHub から取り込む

**設定 → Piem → Extensions** は GitHub URL からスキルを直接取り込みます：
リポジトリかサブフォルダを選び、計画を確認すると、Piem は `SKILL.md` ファイル
を来歴のサイドカーとともに `Piem/skills/` に書き込みます。そのサイドカーが、
後で **Update** ボタンが再取得できるようにするものです。

フォルダ URL は、URL が一つのスキルを指していてもコレクションを指していても、
`SKILL.md` をその Markdown 参照とともに取り込みます。単一ファイルの URL はその
ファイルだけを取り込みます。スクリプトやその他の非 Markdown ファイルはダウン
ロード前にスキップされます。取り込みは 10 スキル、40 Markdown ファイル、
1 ファイルあたり 256 KiB に制限されます。特大のパッケージは、Markdown リソース
を黙って失う代わりに失敗します。書き込みの失敗は、成功したインストールを主張
することなく報告されます。

参照が欠けている古い単一フォルダの取り込みには、**Update** を選びます。Piem は
上流のツリーが変わっていなくてもファイルセットを確認し、既存のインストール
ディレクトリを保ちます。ローカルの変更は依然として衝突を起こします。

## プロンプトテンプレート

プロンプトテンプレートはあなたのボールト内の `Piem/prompts` にあり、同じ `/`
オートコンプリートに、そのソースのラベル付きで現れます。

テンプレートとスキルが名前を共有する場合、テンプレートが優先を保ち、スキルは
`/skill:name` として引き続き到達可能です。オートコンプリートでそれを選ぶと、
曖昧さを解消した形が挿入されます。

## MCP サーバー

Piem は Streamable HTTP でリモートの MCP（Model Context Protocol）サーバーに接続
し、それらのツールをエージェント自身のツールセットに統合します。**設定 → Piem
→ Extensions** で設定します：各サーバーは http(s) URL、任意のベアラートークン、
有効化スイッチです。

- ツールはモデルに `mcp_<サーバー>_<ツール>` として現れるので、読み手はどの
  会話記録でもリモートツールとボールトツールを見分けられます。既存ツールとの
  名前の衝突は数値接尾辞で解決されます。
- 各サーバーの名前にはステータスバッジがあります：ツール数付きの **接続済み**、
  **接続中**、**接続失敗**、**未接続**、または **無効**。有効化スイッチは Piem
  が接続すべきかを制御し、バッジは結果を報告します。接続エラーは名前の下に留ま
  ります。
- 設定を保存すると、チャットを開く前でも有効なサーバーに接続します。同じ URL と
  トークンで既に接続済みのサーバーはそのままにされ、編集された、または失敗した
  サーバーは再接続します。保留中のサーバーの横の **接続** と、失敗したものの横の
  **接続を再試行** で、すぐにもう一度試せます。新しいメッセージもツールセットを
  更新します。定期的なバックグラウンドの再試行はありません。
- サーバーエディター内の **テスト** は、保存せずに下書きの設定を検査します。
- ベアラートークンはプロバイダーの API 鍵と同じ、保存時封印のライフサイクルに
  従います。[セキュリティとプライバシー](security.ja.md#あなたの鍵はどこにあるか)を参照。
- タイムアウトは有界です：接続とツール一覧に 15 秒、ツール呼び出しごとに 120 秒、
  ツール出力は他のすべてのツールと同じバイト予算に切り詰められます。

### なぜリモートのみか

stdio トランスポートはありません。それは子プロセスを起動することになり、それは
モバイルでは禁じられています——このプラグインが二の次ではなく一級である場所で
す。携帯電話に存在できない能力は、デスクトップ限定の不意打ちとして出荷する
のではなく、全員に対して拒否されます。

OAuth フローもありません。静的なベアラートークンは、個人のボールトが現実的に
やり取りするサーバーをカバーし、それが置き換えるフローは、Obsidian がホストする
のに向かないブラウザの往復になるでしょう。

## 組み込み Pi 拡張

Piem には Pi の元々の **bookmark（ブックマーク）** 拡張が含まれます。会話を開き、
Obsidian のコマンドパレットを使います：

- **Piem: 最新の返信をブックマーク** —— 1〜160 文字のラベルを入力します。
- **Piem: 最新のブックマークを削除** —— 最後にラベル付けされたエントリから
  ラベルを取り除きます。
- **Piem: 会話のブックマークを表示** —— ラベルと返信の抜粋を検索し、一つ選んで
  読みます。長い返信は最初の 4,000 文字を表示します。

拡張は既存の会話ファイルを使います。ラベルは再読み込みを越えて生き残り、その
ファイルとともにボールト同期で運ばれます。フォークは、その返信がコピーに含ま
れるラベルを持ち運びます。保存は、保存前にチャットを切り替えても、ダイアログを
開いた会話に属します。Piem は書き込みが完了した後にのみ成功を報告します。書き
込みの失敗はラベルを再試行できるまま残します。これらのコマンドを使う前に、会話
の返信、再試行、圧縮が終わるのを待ってください。

選択は Pi の元々の規則に従います：**会話ログ全体で最後に追記されたアシスタント
の返信**。巻き戻しの後に保持された返信を含みます。それは現在表示されている最後
の返信と異なることがあります。ブックマークの削除も同様にすべてのエントリを後ろ
向きにたどります。ラベルが割り当てられた時刻は使いません。同じラベルへの同時
編集の同期は、既存のセッションマージ規則に従います：到着したファイルが勝ちます。
同期はクロスデバイスのトランザクションではありません。

ブックマークはオフラインで動きます。七つのコミュニティ拡張も同梱され、既定で
有効です。診断共有は **拡張機能** にオフスイッチがあります：

| 拡張 | 何をするか | 使い方 |
| --- | --- | --- |
| `pi-assistant-provenance` | 以前の返信が別のモデルから来たことをモデルに伝える | 自動、リクエストコンテキスト内のみ |
| `pi-model-switch` | 設定済みモデルを一覧・検索・切り替え | エージェントに `switch_model` を使わせる |
| `pi-invisible-continue` | モデル向けのプロンプトテキストを加えずに現在のタスクを続ける | `/continue`、または **Piem: 現在のタスクを続ける** |
| `pi-web-search` | 現在のプロバイダーで検索しソースリンクを返す | エージェントに `web_search` を使わせる |
| `pi-clarify` | 荒い要求を編集可能な下書きに書き換える | `/clarify <アイデア>`、または **Piem: 送る前に下書きを書き換える** |
| `pi-context` | チェックポイントを保存し、タイムラインを検査し、要約ブランチから続ける | エージェントに `context_checkpoint`、`context_timeline`、`context_compact` を使わせる |
| [`b1tank/pi-otel`](https://github.com/b1tank/pi-otel) | エラー報告とパフォーマンスデータを Piem のメンテナーと共有する | 既定でオン；**拡張機能** で **エラー報告とパフォーマンスデータを共有** をオフにすると停止 |

切り替えは、API 鍵を持つ曖昧さのない設定済みモデルに限られます。それはその会話
の次のモデルリクエストを変え、既定の選択を保存します。新しく選ばれたプロバイ
ダーは Piem の既存のトランスポートを通じて会話を受け取ります。上流でゼロと表示
される価格は、無料ではなく不明を意味します。保存の失敗は失敗したツール呼び出し
として報告されます。他のチャットで既に進行中のリクエストは、そのモデルを保ちま
す。

`/continue` は、既存の会話と Piem の通常のノートコンテキストを伴う普通のモデル
リクエストを送ります。返信が走っている間は会話のキューで待ちます。停止はそれを
取り除きます。その空のマーカーはチャットとともに保存されますが、再度開いた後も
含め、プロバイダーのリクエストからは除かれます。`/continue status` と
`/continue help` は上流の診断を表示します。テンプレートやスキルがその名前を共有
する場合、その既存コマンドが短い名前を保ちます。`/extension:continue` を使うか、
スラッシュメニューから拡張を選んでください。

`web_search` は現在のモデルの資格情報を再利用します。そのエンドポイントは
OpenAI Responses または Anthropic Messages を通じてネイティブ検索に対応しなけ
ればなりません。普通の Chat Completions エンドポイントは、チャットできるからと
いって検索できるわけではありません。検索には追加料金がかかることがあります。
クエリと与えられた URL は、チャット履歴の余分なコピーなしにそのプロバイダーへ
行きます。非対応のプロバイダーは明示的に失敗します。Piem が別のプロバイダーを
選ぶことはありません。上流の Gemini 専用の `url_context` ツールは、Piem の設定
済みプロトコルでは存在しません。既知の URL を読むには `web_fetch` を使ってくだ
さい。

`/clarify <アイデア>` は与えられた語を書き換えます。コマンドパレットのアクション
は現在のコンポーザーの下書きを書き換えます。要求に `-clarify` を加えても下書きが
返ります。それを編集し、いつ送るか選べます。停止、パネルを閉じる、チャットの
切り替えは、遅れて届いた結果が別の下書きを置き換えるのを防ぎます。待っている間
に編集すると、あなたの新しい語が残り、使われなかった書き換えがエラーメッセージ
に現れます。書き換えはその下書きと上流の書き換え指示だけを使い、あなたのチャット
履歴やアクティブなノートは使いません。元の指示は言語と意図を保ちますが技術用語
を強調するので、普通のノート書きの要求では結果を見直してください。

既定では、書き換えは会話のモデルを使います。`/clarify model <プロバイダー>
<モデル>` は、既に設定され資格情報のあるモデルをピン留めします。`/clarify model
reset` は既定を復元します。この選択はプラグイン設定に保存され、再読み込みを越え
て生き残ります。ピン留めされたプロバイダーは、チャットが別のプロバイダーを使う
ときでも下書きを受け取ります。

`context_checkpoint` は成功を報告する前にラベルを保存します。`context_compact`
は要約ブランチを保存し、それを選び、タスクを続けるために新しいモデルリクエスト
を出します。古いブランチは会話ファイルに残ります。ボールトのノートや外部の変更
は決して巻き戻されません。停止は保留中の継続を取り消します。既に進行中のボー
ルト書き込みは完了できます。表示される履歴はそのとき保存された結果に従います。
`/context` または **Piem: 会話のコンテキスト使用量を表示** は、Piem の既存の
コンテキスト表示を開き、上流のターミナル専用画面を置き換えます。

スキルやテンプレートが拡張コマンドの名前を共有する場合、それは短い名前を保ちま
す。`/extension:clarify` または `/extension:context` を使って拡張を明示的に選ん
でください。

`b1tank/pi-otel` は固定された Git コミットからインストールされ、他の拡張と同じ
レビュー済みのファクトリーローダーを通じて同梱されます。そのソースは Piem に
コピーも移植もされておらず、同名の npm パッケージでもありません。既定で
`https://otlppiem.shangxin.me` へ OTLP/HTTP JSON を送ります。送信先は固定です。
新しい報告を止めるには[設定](settings.ja.md#extensions)で共有をオフにします。
コンテンツ取得はオフですが、モデルのエラーメッセージにはノートのテキストが含ま
れることがあります。[セキュリティとプライバシー](security.ja.md#opentelemetry-の送信)を
参照。そのイベントはメインの会話をカバーし、すべての内部サブエージェントの
モデル呼び出しではありません。

これらの拡張は `main.js` で出荷され、通常のプラグインリリースでのみ変わります。
Piem はボールトや URL から JS/TS 拡張をダウンロードしたり実行したりしません。
`aliases.json` や来歴の `config.json` のような上流の設定ファイルはマウントされ
ません。これらの拡張は既定の動作を使います。

メンテナー向けには、[ブリッジガイド](pi-extension-bridge.md)が、サポートされる
契約、ソース監査、検証を説明します。Pi の元々のファクトリーローダー、ランナー、
イベントバス、ツールラッパーが再利用されます。ブックマークアダプターもコミュニ
ティアダプターもこのホストを使います。既存の Pi エージェントとセッションストア
が引き続き権威です。帰属については[サードパーティ通知](../THIRD_PARTY_NOTICES.md)を
参照。

## 組み込みスキルを開発する

リポジトリの `skills/<名前>/SKILL.md` が信頼できる情報源です。`name` と
`description` の frontmatter を持つ有効なフォルダを追加すれば、TypeScript の登録
なしにビルドがそれを発見します。Markdown 参照とテンプレートは相対パスを保ちな
がら、そのスキルとともに運ばれます。ビルドの検証は、欠けたメタデータ、安全でない
パス、スクリプト、シンボリックリンク、欠けたリンク先リソースを拒否します。

`npm run build` は `dist/builtin-skills.json` を書き、そのダイジェストを
`main.js` に固定します。`npm run check:skills` は両方をソースに対して検証します。
リリースワークフローは標準のプラグインファイルとともにリソースを公開し、証明を
付けます。

`npm run dev` は追加、編集、削除を監視し、同じ JSON を `main.js` の隣に書きます。
両方のファイルを開発用プラグインフォルダにコピーして Piem を再読み込みします。
開発バンドルは未公開のリリースではなくローカルの JSON を読みます。本番バンドル
は常にインストールされたバージョンに一致するリリースを使います。
