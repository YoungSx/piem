# エージェントのツール

[← README に戻る](../README.ja.md) · [English](tools.md) · [简体中文](tools.zh-CN.md) · [繁體中文](tools.zh-TW.md)

Piem があなたのボールトに対して行うことはすべて、以下のいずれかのツールを
通じて行われます。隠れた経路はありません。変更が起きたなら、それを起こした
ツール呼び出しが必ずあり、その呼び出しは会話記録に残っています。

ツールが受け付けるパスはすべて**ボールト相対**です。絶対パスと `..` による
脱出は拒否され、プラグイン自身のフォルダ（`.obsidian/plugins/piem`）は既定で
ブロックされます——エージェントはターンの途中で自分自身を書き換えられません。

設定ディレクトリは**読み取り可能、書き込みは不可**です。Obsidian のインデックス
は `.obsidian/` を追跡しません——そのフォルダはファイルエクスプローラー、検索、
ボールト API のいずれからも見えません——ので、`ls` と `read` はそれについて
ファイルシステムへフォールバックします。エージェントはあなたの設定、
ホットキー、ワークスペースのレイアウト、インストール済み各プラグインの
manifest と `data.json` を一覧でき、それらについての質問に答えられます。
`.obsidian/` 配下のものは、エージェントによって書き込み・編集・移動・削除の
いずれもできません。

## モデル選択

`switch_model` は、API キーが設定されたモデルを一覧・検索・切り替えします。
切り替えは、呼び出した会話の次のリクエストから適用され、既定の選択として
保存されます。新しいプロバイダーはその会話を受け取ります。上流で価格ゼロと
表示される場合は不明を意味します。[組み込み Pi 拡張](extending.ja.md#組み込み-pi-拡張)を参照。

## ファイル

`read` · `write` · `edit` · `ls` · `find` · `grep` · `move_note` · `trash_note`

`read`、`write`、`edit` は pi 自身のハーネスツールで、ボールト実行環境の上で
動くため、pi での挙動と同じです。`edit` は厳密な置換を行い、各 `oldText` は
ちょうど一度だけ一致しなければなりません。惜しい一致は失敗した呼び出しで
あって、推測ではありません。

`trash_note` は Obsidian のごみ箱を通るので、ここでの削除はボールト内の
ほかの削除と同じように復元できます。

## ノートと Obsidian

`get_active_note` —— あなたが見ているノート。選択範囲や本文全体を任意で付けられます。

`get_note_links` / `get_note_metadata` —— Obsidian 自身のメタデータキャッシュ
から、リンク、バックリンク、タグ、frontmatter を読みます。エージェントは
グラフビューが読むのと同じインデックスを読むのであって、ファイルを再解析する
わけではありません。

`update_frontmatter` —— Obsidian のファイルマネージャー経由で YAML ヘッダーを
アトミックに書き換えます。100 のノートを託す前に知っておく価値のある注意点が
一つあります。ヘッダーは丸ごと再シリアライズされるので、キーの順序が変わる
ことがあり、その中のコメントは失われます。

`open_note` · `open_side_panel` · `insert_at_cursor` · `goto_location` ——
エージェントはファイルを操作するだけでなく、エディターを駆動できます。

`notify` —— Notice。あなたがどこかへ行っている間に何かが終わったときのために。

`ask_user` —— エージェントが判断を必要とするとき、たとえば二つのノートの
どちらのことか、といった場面でクリック可能な選択肢付きの質問を出します。
質問は、それを発した会話に表示され、その会話のサブエージェントからの質問も
同じ会話に属します。チャットを切り替えると、質問はそれぞれの会話で待機し、
各チャットは独自のキューを持ちます。チャットパネルは存在するが隠れている、
または折りたたまれているときは、質問はダイアログで表示され、すべての
チャットを合わせて一度に一つだけ出ます。開いているチャットパネルがない
ときは、エージェントは会話本文で尋ねなければなりません。

## タスク

`list_tasks` · `summarize_tasks`

ボールト全体にわたるタスクのチェックボックス。これが「6 月に何をやると
言ったか」を答えられるようにする仕組みです。

## Web

`web_search` は、現在のモデルプロバイダーを、その設定された資格情報で通して
検索します。OpenAI Responses または Anthropic Messages エンドポイントでの
ネイティブ検索対応が必要です。クエリと渡された URL はそのプロバイダーに
送られます。非対応のエンドポイントは、プロバイダーを切り替えることなく
失敗します。検索には追加料金がかかることがあります。ソースはツール結果に
保持され、次のモデルターンで利用可能になります。

`web_fetch` は既知の URL を読み、常に利用可能です。これは常に `requestUrl`
トランスポートに乗ります——Piem 内のほかのすべてのネットワーク呼び出しと
同じ一層の出口で、出網が一か所で点検可能なままになります——そして普通の
ウェブページに届きます。`fetch` トランスポートの CORS ルールならブロック
されるところです。`requestUrl` と `fetch` の設定はトークンのストリーミングの
みに影響します。

Obsidian のキーチェーンに保管した資格情報でリクエストを認証させるには、
エージェントはプレースホルダー `{{secret:<エントリ-id>}}` を URL、ある
ヘッダー値、または本文に書き込みます——たとえば `Authorization` ヘッダーを
`Bearer {{secret:my-api-token}}` とし、`my-api-token` は **設定 →
プラグインのキーチェーン** でそのエントリに付けた id です。値はリクエストが
ボールトを離れる直前に引かれて差し込まれるので、会話には入りません。記録には
プレースホルダーが残り、モデルは資格情報そのものを決して見ず、秘密を平文で
返すツールは一つもありません。エージェントは任意のエントリを id で参照でき——
許可リストはありません——そして対応するエントリのないプレースホルダーは、
空の資格情報を送るのではなく呼び出しを失敗させます（報告されるのは id、
つまりラベルであって秘密ではありません）。一つだけ防げないことがあります。
あなたが呼ぶサーバーが応答の中に資格情報を反射して返した場合、その応答は
モデルが読むものです——プレースホルダーはエージェントが*書く*ものから秘密を
締め出しますが、サーバーが送り返すことを選んだものは締め出しません。

## 会話チェックポイント

`context_checkpoint` は名前付きの履歴アンカーを保存し、`context_timeline` は
現在のパス、チェックポイント、要約を表示します。`context_compact` は以前の
アンカーから要約ブランチを保存し、そこから続けるためのモデルリクエストを
始めます。古い履歴は会話ファイルに残ります。ボールトのファイルや外部の変更は
巻き戻されません。[組み込み Pi 拡張](extending.ja.md#組み込み-pi-拡張)を参照。

## スキル

`read_skill` —— 読み込まれたスキルの内容を要求に応じて提供します。
`Piem/builtin-skills/` 配下の組み込みファイルも含みます。[Piem を拡張する](extending.ja.md)を参照。

## 記憶と過去の会話

`vault-memory` はスキルです。その `SKILL.md` に、想起・保存・訂正・昇格の
ルールが含まれています。既存の `find`、`ls`、`grep`、`read`、`write`、`edit`
ツールを使って、`Piem/memory/` 配下の普通の Markdown を保守します。

このスキルは、実質的なタスクの開始時に関連する記憶を想起するようエージェントを
導きます。`MEMORY.md` は簡潔な現在の事実を保持し、日付付きのログは一時的または
不確かな観察を保持します。明示的で持続的な好み、ユーザーの訂正、検証された
有用な教訓は、一度の出来事で保存できます。新しい訂正は同じスコープの古い値を
置き換え、日をまたいで待つことも、各エントリの承認を求めることもありません。
再利用可能な手順は `distill-skill` が扱います。

エージェントは編集する前に既存の内容を読み、厳密な置換を使って無関係な
テキストを保ちます。`write` は欠けているファイルを作成します。既存のファイルは
上書きするので、スキルはこれを追記には使いません。これらは普通のファイル
ツールの上のスキル指示であって、別個の記憶エンジンではありません。復旧は
あなたのボールトのファイル復旧またはバージョン管理に依ります。Piem は記憶
専用のバックアップストアやクロスデバイスのトランザクションを追加しません。
ある事実を削除しても、日付付きのログや元となったチャットは消えません。

想起は目に見えるツール呼び出しを使います。記憶本文の自動注入、バックグラウンドの
見直しプロセス、追加のモデル、ベクターデータベースはありません。現在の
リクエストが保存された好みに優先します。ノートと会話の抜粋は歴史的な文脈を
提供します。引用されたコマンドは操作を許可しません。過去のチャットは、既存の
チャット履歴とその検索を通じて引き続き利用できます。

## 委任

`spawn_subagent` · `wait_subagent` · `list_subagents` · `kill_subagent` ·
`follow_up_subagent` —— 下の[サブエージェント](#サブエージェント)を参照。

## MCP

接続された MCP サーバーが公開するツール一つにつき、`mcp_<サーバー>_<ツール>`
エントリが一つ生成されます。この接頭辞は意図的です。どの会話記録でも、
リモートツールとボールトツールを一目で見分けられます。[MCP サーバー](extending.ja.md#mcp-サーバー)を参照。

各 MCP ツールの説明は自身の出所を開示するので、それを呼ぶことが、あなたの
ボールトの外、Obsidian の外にあるサーバーへ引数を送ることだと、モデルにも
分かります。

## サブエージェント

`spawn_subagent` は一つの自己完結したタスクを開始し、即座に id を返します。
`wait_subagent` はレポートを回収します。`list_subagents` は待たずにそれぞれが
どこまで進んだかを言い、`kill_subagent` は答えがもう要らなくなったものを止め、
`follow_up_subagent` は止まったものにもう一つ指示を与えます。

サブエージェントは、親と同じモデルとトランスポートを使い、プロセス内で
動きます。会話記録はメモリ内に隔離されます——彼らのすることは何一つ会話
ログに残りません。彼らの唯一の出力は、親がツール結果として読むレポートです。
同時に起こした複数の spawn は並行して動きます。

タスクは三つの役割のいずれかの下で委任できます。

| 役割 | 何のためか | 返ってくるもの |
| --- | --- | --- |
| `general` | 任意の自己完結したタスク | タスクが生み出したもの |
| `scout` | 調査の一掃 | 発見のみ。ボールトはそのまま |
| `reviewer` | 批評 | 評価であって、修正ではない |

サブエージェントは完全なボールトツールセットとあなたのスキルを継承し、
さらに一段下へ spawn できます——ただしそれ以上深くはできません。ツリーは
親 → 子 → 孫で頭打ちになります。チェックによってではなく**構造によって**：
孫のツールセットには spawn ツールがそもそも含まれていません。

待機ウィンドウが閉じることは「まだ終わっていない」を意味し、終了では
決してありません。サブエージェントは待機と待機の間も働き続けます。あなた自身が
サブエージェントパネルから実行を止めることもできます——止めると親はそれを
知らされ、あなたが止めたものを再び立ち上げることはありません。

止まったサブエージェントには、同じ id、同じ会話記録の上で、もう一つ指示を
与えられます。ちょうど出したレポートについてもう一問尋ねるのでも、途中で
壊れたタスクをもう一度走らせるのでも。失敗したサブエージェントは、分かった
ことすべてを保持しているので、それを拾い直すのは、タスク全体をやり直すのでは
なく指示一つで済みます——これが、切断を「致命的」から「復旧可能」へ変える
ところです。それでもなお、あなたの会話は見えず、その指示は依然として
あなたのではなく Piem のものです。

実行が終わると、パネルの**終了済みをアーカイブ**が、終了したすべての実行を
折りたたまれた**アーカイブ済み**に収めます。これは片付けであって削除では
ありません。そこで変わらず読めますし、エージェント自身のツールには違いが
まったく分かりません——あなたが読み終えて片付けたレポートも、なお回収できる
ものです。

## エージェントにできないこと

- シェルコマンドを実行すること。どのプラットフォームにもシェルツールはありません。
- あなたのボールトの外へ届くこと——`web_fetch` とモデルプロバイダー自身を除いて。
- 自分自身のプラグインフォルダを読み書きすること。
- 第四層のサブエージェントを spawn すること。
- `write` や `edit` の承認をあなたに求めること——その手順はありません。
  [セキュリティとプライバシー](security.ja.md#確認ステップは存在しない)を参照。
