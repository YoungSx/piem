# 設定

[← 回到 README](../README.zh-TW.md) · [English](settings.md) · [简体中文](settings.zh-CN.md) · [日本語](settings.ja.md)

**設定 → Piem** 下有四頁：Models、Chat、Extensions、General。

## Models

這是你唯一必須造訪一次的頁面。其餘一切都有可用的預設值。

**Providers（供應商）**是你自己的端點——Piem 不代管任何服務。一個供應商由三樣東西組成：一個基礎 URL、一個 API key，以及一種傳輸協定：

| 協定 | 適用於 |
| --- | --- |
| `openai-completions` | 相容 OpenAI 的 `/chat/completions` 端點 |
| `openai-responses` | OpenAI 的 Responses API 及相容端點 |
| `anthropic-messages` | Anthropic 的 Messages API 及相容端點 |

**預設（Presets）。** 從十六個已知服務中挑一個，剩下要填的就只有它的 API key——表單會隱藏名稱、基礎 URL 和協定三列，因為預設已把這三者都定好了。包含 Anthropic、OpenAI、Google Gemini、DeepSeek、Groq、Mistral、Moonshot、xAI、Z.ai、OpenRouter、MiniMax、Qwen，以及其中四家另外經營的中國大陸站點。每個選項都標明它連向的主機，因為那正是區分同一廠商兩個服務的依據。

**Custom（自訂）**排在列表最前，也是新表單開啟的地方。它同時也是你接管某個預設端點的方式：切換到 Custom，那三列就會回來，仍保留著預設填入的內容，可供編輯。在 Custom 列裡輸入某個預設自己的 URL 會選中那個預設，而編輯離開它則會退回 Custom——標籤永遠不會描述一個表單並未持有的端點。挑選預設絕不會動到你的 key。

Model id 由端點自身建議，只要它有實作列出功能——你自己的伺服器比這個外掛能內建的任何東西都更清楚它會接受什麼，也是唯一知道私有閘道的一方。無論如何，這個欄位都接受你輸入的任意 id。

**能力建議。** 對於已知的 model id，表單會從一份即時的 [models.dev](https://models.dev) 索引（涵蓋它追蹤的每一家供應商）填入它是否接受影像輸入、它的上下文視窗，以及它的最大輸出。任何你手動設定的值都凌駕於建議之上，並阻止它再度被覆寫；而當索引無法連線時，每個控制項都有可用的預設值。

**連線測試**會透過你為供應商請求所選的傳輸方式來探測端點——就是你的對話會走的同一條通道，而非圖方便的替代品。一個在 `fetch` 上通過、而你的對話卻走 `requestUrl` 的測試，測的是錯的東西。

**Prompt cache（提示快取）**決定供應商可以把提示中不變的部分——系統指令、工具定義、技能、你開著的筆記——保留多久，好讓後續請求以大約十分之一的價格讀回它，而不是付全額。

預設是**一小時**，這刻意不同於底層 agent 函式庫的預設值。五分鐘對於一個回合間隔僅數秒的終端機 agent 才恰當；它會在你於兩個問題之間花十分鐘寫東西時就過期，接著整個提示又被重新全額計費。一小時的儲存成本較高——Anthropic 對一小時快取寫入收取兩倍基礎輸入費，對五分鐘則收 1.25 倍——而第二次後續請求會把這筆溢價賺回來。若你的工作階段真的只有一個問題那麼長，就選**五分鐘**；對於拒絕快取標記的端點，則選**關閉**。

供應商會把這個偏好對映到它們各自支援的方式，並忽略它們不支援的，所以這裡的設定不取決於你選了哪個模型。開啟**顯示 agent 詳情**後，只要供應商有回報，上下文環的彈出視窗就會標明以一小時費率寫入的份額——這是設定確實生效的唯一證明，因為一個忽略它的供應商只會用更便宜的方式計費。

## Chat

行為在上，儲存在下。

這裡有兩件事不需要開關就會發生，兩者都值得一提。你開著的筆記會被注入**每一個**回合——它的路徑和它的正文——所以你永遠不必說「我正在看的那則筆記」。而當上下文視窗填滿時，對話會自我整理；命令面板裡的*整理先前的思緒*可按需做同樣的事，而逐字稿會把每次整理記錄成一道你可以展開閱讀其摘要的接縫。

- **顯示 agent 詳情** — 在對話面板中顯示 token 計數、花費，以及原始的工具引數。預設關閉；當你想看 agent 實際送出了什麼時再開啟。
- **展開工具活動** — 有多少機器流量一開始就是展開的：思考、工具呼叫、結果。所有東西預設都摺疊，任何一列仍可手動展開。在該模式下，兩個或更多連續的思考與工具呼叫會摺成單獨一列，說明這段執行做了什麼——「讀了一則筆記並想通了」——原始各列在裡面，依序排列。一個失敗的呼叫和一個被回答的問題會留在摺疊之外：兩者都不該讓人多點一下才看得到。
- **回覆中途送出** — 一則你在 Piem 還在回答時送出的訊息不會被拒絕；它會等待，而這裡設定的就是等多久。*整個回答完成後*是預設也是安全的：回覆完成它的計畫後，你的訊息才被當作下一個問題來讀。*目前這次請求完成後*則更早——訊息會在這一回合的工具之後、Piem 再次開口之前落地，這能在一長串工具呼叫進行到一半時改變其方向。兩個設定都不會中斷：等待中訊息上的**送出**動作才會，它把回覆截短，好讓那一則訊息立即送出。
- **上下文整理** — 決定何時把對話摘要以騰出空間的保留額度與留存額度。Piem 會針對你為模型設定的上下文視窗來規劃。
- **保留的對話數** — 一個留存上限。當你在超過上限後開啟新對話時，最舊的那些會移到垃圾桶。把它設為無限，就永遠不會丟棄任何對話。
- 工作階段目錄顯示在這裡，所以你隨時知道哪個資料夾裝著你的逐字稿。

## Extensions

MCP 伺服器、技能匯入，以及內建技能檔案。**內建技能檔案**顯示準備狀態，以及任何因本機變更而保留的檔案。**重試準備**會重試失敗的下載；**還原缺失檔案**會還原被刪除的內建項目而不覆寫你的編輯。**重新載入**會重讀本機技能。路徑、優先順序與更新規則見 [擴充 Piem](extending.zh-TW.md)。

**分享錯誤報告與效能資料**預設開啟。它會把模型與工具名稱、用量、時序與錯誤送給 Piem 的維護者，位於 `https://otlppiem.shangxin.me`。關掉它可立即停止新報告並丟棄未送出的資料；已經送出的請求無法收回。重新開啟後，在 **設定 → 社群外掛** 下**重新載入 Piem** 以恢復分享。目的地是固定的，無法在設定中編輯。閘道驗證已預先設定好，所以不需要任何帳號或收集器憑證。

隨附的原始 [b1tank/pi-otel](https://github.com/b1tank/pi-otel) 擴充使用 OTLP/HTTP JSON，位於 `/v1/traces`、`/v1/metrics` 和 `/v1/logs`。指標每 60 秒匯出一次；追蹤與日誌各自分批。內容擷取維持關閉，但模型的錯誤文字仍可能含有筆記內容。見[資料揭露](security.zh-TW.md#opentelemetry-發送)。這並不提供完整的子代理追蹤，也不保證最後一批資料能在緩慢的關閉過程中送達。

## General

- **語言** — 英文或簡體中文。預設跟隨 Obsidian 自身的語言；這裡的覆寫是為了你想讓外掛使用與應用程式不同的語言時。
- **送出快捷鍵** — `Enter` 送出，或 `Ctrl`/`⌘`+`Enter` 送出而讓 `Enter` 插入換行。挑你已有的肌肉記憶對應的那個。
- **日誌等級**與**日誌檢視器** — 日誌檢視會以自己的一個 leaf 開啟，是供應商出狀況時第一個要查看的地方。
- **關於** — 執行中的版本（從 `manifest.json` 讀取，絕不另行複述）、連結、離開你 vault 的內容摘要，以及你的 key 如何儲存在這台裝置上。

## Commands

Piem 加進命令面板的一切，顯示為 *Piem: …*：

| 命令 | 作用 |
| --- | --- |
| Open chat | 開啟對話側面板 |
| Open log view | 開啟日誌 leaf |
| New chat | 開始一段全新的對話 |
| Stop response | 中止進行中的回合 |
| Tidy earlier thoughts | 手動壓縮對話 |
| Focus chat input | 把游標跳進輸入框 |
| Ask about selection | 把選取的文字與筆記路徑加進你的草稿 |
| Ask about this note | 把目前筆記的路徑加進你的草稿 |

它們全都可在 **設定 → 快捷鍵** 下綁定你自己的熱鍵。

### 從右鍵選單提問

在 Obsidian 的檔案選單中使用 **Ask about this file**、**Ask about this folder** 或 **Ask about these items**。編輯器在有選取文字時提供 **Ask about selection**，否則提供 **Ask about this note**。外部 HTTP/HTTPS 連結提供 **Ask about this link**。

每個動作都會在文字輸入框內、問題上方加入一張可展開的引用卡。這些卡片與文字共用同一個焦點框。展開一張卡片可檢視它完整的路徑、URL 或擷取的選取內容；移除它則把它排除在下一個問題之外。你自己的字句維持不變。當問題就緒時選擇**送出**。開啟選單或加入卡片並不會抓取網頁或啟動模型請求。

卡片屬於草稿，並在你關閉面板或切換對話後續存。第一張技能卡或引用卡會存下一段新對話的身分，所以它未送出的草稿在重啟 Obsidian 後也能取回。開啟一段未經觸碰的空白對話則什麼都不會存。它們會隨著排隊中的問題一起移動，在你把排隊問題取回時回來，並出現在已送出問題的氣泡裡，使用與技能內容相同的揭露樣式。選取一個技能，或以一個空格補全一個已知的 `/skill:name` 命令，會把它變成同樣可展開的卡片，放進文字輸入框內。文字區接著就只剩你的問題。移除技能卡會移除那次呼叫，並保留問題與其他引用。已存的草稿仍是卡片與所送出技能的真相來源；這種分組在重新載入對話後續存。Pi 的原生自訂訊息為模型儲存引用文字，並為卡片分開儲存中繼資料。檔案與資料夾卡片標明路徑；它們並不聲稱其完整內容已被讀取。選取卡片維持選取時的原樣。

一份草稿最多接受 64 個引用與 20,000 個字元的引用資料。草稿文字維持它既有的續存上限：前 20,000 個字元會被儲存，而開著的編輯器保留全文。重複的引用會被合併。超出額度的加入會被拒絕並附上說明，而無法取得的項目會被回報。過長的選取會被裁剪到 2,000 個 Unicode 字元並附上通知。獨立的 **Pin** 控制項仍支援最多八個持久的檔案引用；加入一張單一問題的卡片不會消耗一個 pin。

當輸入框已存的草稿正在載入時，它維持唯讀。在行動裝置上，加入一個引用會開啟一個摺疊的輸入框並聚焦到問題。送出後，`web_fetch` 可請求一個連結的網頁，受站點存取限制與工具文字上限規範。作用中筆記的開啟編輯器提供它最新的文字，包含未儲存的編輯；已關閉的筆記使用 vault 副本。選單的可用性跟隨 Obsidian，所以自訂檢視與行動裝置手勢可能顯示不同的項目。

## Storage

工作階段是位於 `<vault config dir>/plugins/piem/sessions/` 下的 JSONL 檔案，以一個相容 pi 的第 3 版標頭與樹狀項目（`id` / `parentId`）寫入——與 pi 所用的形狀相同，所以一份逐字稿不會被困在這個外掛裡。

未送出的草稿文字與引用卡活在日誌旁邊的每對話一份的 `drafts/<session-id>.json` 檔案裡。關閉面板會保留兩者；較舊的純文字草稿仍可讀取。

暫存的影像**絕不**續存。工作階段日誌儲存一個佔位符而非位元組，所以一個會同步的 vault 不會把你的螢幕截圖帶著到處跑。

## Versions

執行中的版本活在 `manifest.json` 裡，並顯示在**關於**中。已發行的版本，以及每個版本所需的最低 Obsidian 版本，列在 [`versions.json`](../versions.json) 裡。
