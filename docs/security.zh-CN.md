# 安全与隐私

[← 回到 README](../README.zh-CN.md) · [English](security.md)

Piem 把你的笔记交给一个模型服务商，并且让一个代理去改它们。这两件事都是重
点，也都值得直说，而不是让你在某个设置页里自己发现。

## 什么会离开你的仓库

发给你配置的模型服务商：

- 你的提示与对话历史；
- **你正打开的那篇笔记**——路径和完整正文——每一轮都发，无论你的问题是否与它
  有关；
- 工具返回的仓库内容——笔记正文、搜索结果、文件清单、frontmatter；
- 代理回顾时读取的记忆和过往对话摘录；
- 工具结果，包括 `web_fetch` 抓回来的东西；
- 你暂存的图片附件。

额外发给某台 MCP 服务器的：由它暴露的那个工具的调用参数。每个 MCP 工具的描述
里都写着这件事，所以模型也知道。

准备内置技能时，会向 GitHub 发送 GET 请求，下载与当前插件版本匹配的资源。
GitHub 及其下载主机会收到资源 URL（包含插件版本）、设备 IP 和普通请求元信息。
这次下载不携带笔记、对话或服务商密钥。资源是经过摘要校验的 Markdown，写入
`Piem/builtin-skills/`；不执行脚本，也不会独立于插件追随更新的 Release。

没有遥测、分析、崩溃上报，也没有 Piem 自营后端。

实践上的结论：**让它对着一个你愿意发给你的模型服务商的仓库。** 搜索碰到哪个
文件就会列出哪个文件，而模型看得见那份清单。

## 没有确认步骤

代理可以直接 `write`、`edit`、`move_note`、`trash_note`。没有对话框，没有等你
批的 diff，没有「你确定吗」。

这是一个刻意的产品决定，不是缺失的功能。你可以这样应对：

- 只在你愿意被改动的仓库上用 Piem。
- 每轮之后读一遍对话记录——每处改动都来自一次工具调用，每次工具调用都在那儿。
- 把仓库放进版本控制，或者靠 Obsidian 的文件恢复。`trash_note` 走的是
  Obsidian 的废纸篓，所以删除按常规办法就能撤回。

## 你的密钥存在哪

记忆笔记是随仓库存储和同步的普通 Markdown。`vault-memory` 技能要求代理避开
密钥和密码，但它不是密钥检测器。恢复依靠你仓库的文件恢复或版本控制。删除
当前事实不会删除每日日志、来源聊天或上述恢复系统中的副本。
见[记忆与过往对话](tools.zh-CN.md#记忆与过往对话)。

API 密钥和 MCP Bearer 令牌随 Obsidian 插件数据存储。

- **桌面端：** 写进 `data.json` 之前先用 Electron `safeStorage` 密封——Windows
  上是 DPAPI，macOS 上是 Keychain，Linux 上是 libsecret。
- **移动端，以及没有钥匙串的桌面：** 明文存在 `data.json` 里。那里没有可以拿
  来密封的东西，而假装有比说出来更糟。

密封过的密钥只能在密封它的那台设备上解开。所以仓库同步**不会**把可用的密钥带
到另一台设备上：每台设备各输一次。这更像是特性而不是限制，但它确实是「为什么
我手机上的密钥是空的」的答案。

优先用受限或低额度的密钥。这一点插件替你强制不了。

## Obsidian 审核会点名的能力

Piem 是一个代理插件，所以做它该做的事，就需要一些 Obsidian 社区插件审核会明确
点名的能力。这里就用审核的同一套词汇把它们列出来。没有一项是缺陷或权宜之
计——每一项都在承载某个功能，而且没有一项会把任何东西发到上面描述之外的地方。

**直接文件系统访问。** 桌面端插件通过 Electron 的 `require` 拿到 Node 的
`fs`，读取用户级技能目录（`~/.pi/agent/skills`、`~/.agents/skills` 和你配置的
额外目录），因为仓库 API 看不到这些文件。`read_skill` 可按需读取所选技能的
UTF-8 文本资源，单文件最多 1 MiB，并校验真实路径仍位于该技能目录内。
绝对路径、隐藏路径、向上跳转和越界符号链接都会被拒绝。读到的文本与其他工具
结果一样发给当前模型，已读取的资源会在压缩后保留。这条访问只读，不提供 shell
执行；普通文件工具仍限制在笔记库内。移动端宿主不提供 `require` 时，用户级
技能显示为不可用，不会导致插件加载失败。

**仓库枚举。** 搜索和任务工具会调 `vault.getFiles` /
`vault.getMarkdownFiles`，它们列出仓库里每个文件的完整路径。只要一次搜索或任
务查询碰到它们，模型就看得见那份清单。这是「搜我的仓库」这件事本身的固有含
义。

**剪贴板访问。** 只出不进：消息回复、日志行，以及设置里的复制密钥操作会调
`navigator.clipboard.writeText`。Piem 从不读剪贴板。粘贴进来的图片走的是编辑
器自己的 paste 事件，不是一次剪贴板读取。

**运行时 base64 编码。** 图片附件在作为模型内容发出去之前用 `btoa` 编码。这就
是它的全部用途——代码里没有任何地方解码混淆过的载荷。

**网络请求。** 大约二十处调用点，全部经由同一个传输层：模型服务商的流、连接测
试、models.dev 目录建议、远程 MCP 服务器、技能导入、内置技能准备，以及 `web_fetch` 工具。你在
`requestUrl` 与 `fetch` 之间的选择只管住真正在乎流式的那部分——模型流和连接测
试；目录、技能导入、内置技能准备和 `web_fetch` 固定走 `requestUrl`，因为它们读的是完整响应，
还必须够得到那些不发 CORS 头的主机。出网行为集中在一处可查，而不是散落在代
码库各处。

内置技能准备在 15 秒后停止等待，不会在失败后循环重试。卸载会取消准备任务，
防止迟到响应发起写文件操作。Obsidian 的 `requestUrl` 无法物理取消已经发出的
请求，因此停止等待后，底层请求仍可能继续完成。已有文件可离线使用；扩展能力
中的 **重试准备** 和 **恢复缺失文件** 是显式的恢复入口。
